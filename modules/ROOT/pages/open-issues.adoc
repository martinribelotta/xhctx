= Open Issues

* *CSR address numbering* -- draft addresses assigned within the
  legitimate Machine custom R/W range (xref:csrs.adoc[Section 3.1]);
  not yet reviewed or allocated by RISC-V International.
* *`miselect` bit layout for the `Smcsrind` window*
  (xref:csrs.adoc[Section 3.3]) -- the `array_sel`/`ctx_id` encoding is
  illustrative; needs confirmation against the implemented `miselect`
  width and against any other custom extensions expected to share the
  same core's custom `miselect` sub-range.
* *S-mode-resident binding* -- out of scope for this draft
  (xref:csrs.adoc[Section 3.1]); would need its own address allocation
  from the supervisor custom ranges and possibly `Sscsrind` instead of
  `Smcsrind`.
* *Access-control granularity* -- M-mode-only is decided for the
  reference binding (xref:csrs.adoc[Section 3.1]); finer-grained
  control (e.g. per-source restrictions on the `SW_TARGET_BASE` range)
  is not yet specified.
* *`ecall` from S-mode* -- left undefined, tracking the general
  S-mode-out-of-scope status above
  (xref:context-lifecycle.adoc[Section 7.2], Case E).
* *`ECALL_BASE` reserved range* -- like `SW_TARGET_BASE`
  (xref:event-fabric.adoc[Section 4.3]), its exact width and placement
  within the `event_id` space is not yet fixed.
* *`mctxctl` `RESTART` targeting `active_ctx`* -- Case F
  (xref:context-lifecycle.adoc[Section 7.2]) reserves
  `target_ctx_id == active_ctx`; whether it should be a no-op, an
  immediate self-restart, or an illegal-instruction exception is not
  yet decided.
